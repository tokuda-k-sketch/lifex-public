## 1. これは何か

LIFEX加盟店（現在16店舗）の営業KPIを、毎週金曜早朝の会議で誰でも見られるようにしたダッシュボード。従来は各店舗へ電話・オンライン会議で数値をヒアリングして口頭共有していたものを、「スプシに入力すれば勝手に反映される」形にした。

- 本番: https://euphonious-selkie-072baa.netlify.app/ （KPIのみ。金曜会議で使用中）
- 開発版: https://prismatic-trifle-834c72.netlify.app/ （KPI＋広告実績。「開発版」バッジ付き）

表示内容:
- 全店舗合計KPI 6枚（①通話接続率 ②アポ取得率 ③契約(内定)率 ＋ 登録起点の全体転換率3種）
- ファネルフローSVG（登録→通話→アポ→面談→契約。円の大きさ＝顧客数。これは徳田さんの発案）
- ステータス定義凡例（S2〜S13の13段階）
- 店舗別カード（ミニファネル・KPI・広告実績・所見）

## 2. アーキテクチャ

```
KPIスプレッドシート（各店舗の数値を手入力）
 └ シート「KPIデータ」… 1行=1店舗、列: 店舗名/担当/S2〜S13の人数/所見
      │
      ▼ Google Apps Script（doGet） … スプシの「拡張機能→Apps Script」に設置
広告スプレッドシート（マーケ部門管理・閲覧権限のみ）
 └ 「月別_反響集計（LP1）」「予約集計（LP1）」を openById で閲覧参照（v2のみ）
      │
      ▼ ウェブアプリとしてデプロイ → JSON配信（アクセス: 全員）
静的HTML 1枚（index.html）… Netlifyでホスティング
 └ fetch でJSON取得 → ブラウザ側JSで全描画
 └ 5分ごと自動更新 ＋ タブ復帰時に即更新（開発版のみ）
```

ポイント: **サーバーもDBも使っていない**。スプシがDB、GASがAPI、Netlifyの無料静的ホスティングが画面。運用コストゼロ。

### GASのバージョン管理（重要）

- GAS v1（本番用・**触らない**）: `https://script.google.com/macros/s/AKfycbwaF-NIhkqRmnk3gDsOhWmpQNfzBBCBi6O_efu3zuwRQpfi_0_hWEdNFW4qxpMMqinJ/exec`
- GAS v2（開発用）: `https://script.google.com/macros/s/AKfycbwriC9V4xS2ZZ8rGhfsQydsBmXKzTWo9CKiJUs7kPt5naU3NWXQy_IKbB6ytZfw_WtE/exec`

GASのデプロイはバージョン固定。同じスクリプトプロジェクト内で「**新しいデプロイ**」を作れば別URLが発行され、既存デプロイ（＝本番）には一切影響しない。この性質を使って、本番会議を止めずに開発版を並走させている。「デプロイを管理」から既存デプロイを更新すると本番が変わってしまうので厳禁。

### データの流れ（v2）

1. `doGet()` がKPIスプシの「KPIデータ」シートを読んで `stores[]` を生成（lifex-apps-script-v2.txt:26）
2. `readAdData()` が広告スプシを `openById` で開き、月別反響集計と予約集計をパースして `ads` を生成（同:84）。**失敗してもKPI配信は止めない**（try-catchで `ads.error` に格納）
3. `{stores, ads, updatedAt}` をJSONで返す
4. index.html の `init()` が fetch → `renderAll()` で描画（index.html:614）。fetch失敗時はサンプルデータ＋警告表示に自動フォールバック

## 4. コード読解ガイド

### index.html の構造

- **CONFIGURATION**（271行目）: `APPS_SCRIPT_URL` にGASのURLを貼るだけの設計。空ならサンプルデータ表示＋セットアップ手順バナーが出る（初回セットアップの導線を兼ねる）
- **KPI計算**（`calcKPIs`、416行目）: ステータス人数からの集計定義がすべてここにある
  - 母数 total = S2〜S13合計 ／ 通話接続 connected = S4〜S11 ／ アポ appt = S5〜S11 ／ 面談 interview = S6〜S11 ／ 契約 contract = S10〜S11
  - つまり「S5にいる人はS4を通過済み」という積み上げ解釈。S12（失注）・S13（対象外）は母数にのみ算入
- **ファネルSVG**（`renderFunnel`、488行目）: 円の半径を顧客数で線形スケール（min20px〜max74px）、円の間に転換率を表示
- **店舗名の表記ゆれ吸収**（`normName`・`findAdName`、325行目）: KPIスプシと広告スプシで店舗名の書き方が違う問題をダッシュボード側JSで解決
  - スペース（全角半角）除去・丸数字→数字・小文字化で正規化一致
  - 「中央建設＋支店名」→「中央建設①〜④」の対応表（出雲=①、松江=②、鳥取=③、米子=④）
  - 「WD」→「WITHDOM Group」のエイリアス
- **広告実績セクション**（`renderAdSection`、353行目）: 店舗カード内にMETA/Googleタブ切替の月次表と単価2種を表示
- **自動更新**（669行目）: 5分間隔の `setInterval`。タブ非表示中はスキップし、`visibilitychange` で表示に戻った瞬間に最新化

### lifex-apps-script-v2.txt（GASコード）の構造

- `findSheetByName`（95行目）: シート名の**末尾スペースゆれ**で一致に失敗した実績があり、空白を除去して比較する方式にした
- `parseMonthly`（110行目）: 広告スプシは「META広告_YYYY年M月」というタイトル行で始まるブロックが縦に並び、同じ行の右側（L列〜）にGoogle広告ブロックが並ぶ変則レイアウト。タイトル行を正規表現で見つけてブロック単位でパース
- `parseReservations`（156行目）: 「加盟店」「コード」が横に並ぶヘッダーを探してその下の表を読む。合計・小計行はスキップ
- `num`（187行目）: `"¥835,900"` `"1.61%"` `"#DIV/0!"` などの表示値を数値/nullに変換

## 5. 指標定義（暫定・確定前の懸案）

広告関連の単価2つは**徳田さんがまだ定義を確定させていない**。西野さんのクロが説明する際は「暫定定義」と必ず添えること。

- 予約単価 ＝ 予約集計タブの累計配信費 ÷ LP予約CV数（「金額列＝累計配信費」という解釈自体が要確認）
- 来場単価 ＝ 累計配信費 ÷ KPIのS6〜S11合計（面談済以降＝来場通過人数とみなす推定。S12/S13に落ちた来場済み客は含まれない）

## 6. 運用手順

- **数値更新**: KPIスプシの「KPIデータ」シートに各店舗の数値を入力するだけ。ダッシュボードは開けば最新（開発版は5分自動更新）
- **HTML更新**: index.htmlを修正 → Netlifyの該当サイトのDeploysページへファイルをドラッグ&ドロップ（徳田さんが手動運用）
- **GAS更新**: コードを置き換え → 必ず「新しいデプロイ」→ 新URLをindex.htmlの `APPS_SCRIPT_URL` に貼り替え
- **店舗追加**: KPIスプシに行を足せば自動で表示される

## 7. 残タスク・既知の課題

- 開発版の数字の妥当性確認 → OKなら本番NetlifyサイトのDeploysに開発版index.htmlをドロップして本番昇格（「開発版」バッジの除去を忘れずに）
- 広告スプシのみに存在する店舗（BJC・建匠・河原工務店など）は現状表示されない（KPIシートに行が増えれば自動表示）
- フラワーホームは広告スプシに存在しない → 広告セクションは「データなし」表示（仕様どおり）
- ヘッダーの「16店舗」は現状ハードコード（index.html:607）

## 8. 取り扱い注意

GASのURLは「知っていれば誰でもJSONを取得できる」状態（アクセス: 全員）。加盟店の営業数値が含まれるため、**URL・スプシID・このフォルダを社外に出さないこと**。Netlify URLも同様に推測困難なだけで認証はない。
